AI 编程工具可以读取文件、执行命令和调用 API。真正安全的使用方式不是“完全不让它做事”，而是让它只在明确的目录、范围和权限内工作，并且每次都能检查和撤销。

## 账号安全

- 使用自己长期能控制的邮箱和恢复方式；
- 不使用共享账号处理私人项目；
- 不把密码、验证码、恢复链接发给任何代登录或代配置的人；
- 发现异常登录、验证循环或账号受限时，优先走官方帮助流程。

## API Key 安全

把 API Key 当作密码：

- 存在本地安全位置或受保护的环境变量中；
- 不写入文章、截图、前端代码或 Git 提交；
- 定期检查用量和调用记录；
- 怀疑泄露时立即撤销旧 Key，不能只改变量名；
- 给不同用途使用不同 Key，方便定位和撤销。

示例只能使用占位符：

```text
<YOUR_API_KEY>
```

## 项目目录安全

- 只把 AI 打开到当前任务需要的项目目录；
- 不要把整个用户目录、下载目录或包含私人资料的父目录交给工具；
- 修改前查看 Git 状态，确认已有未提交修改；
- 任务中写清允许修改的文件和禁止触碰的目录；
- 先看 diff，再接受修改。

## MCP 和外部工具安全

第一次配置外部工具时，优先选择只读 Server：

1. 先确认 Server 来源和代码/文档；
2. 只开启当前任务需要的工具；
3. 不把生产数据库、支付系统或私人网盘作为第一个练习；
4. 记录配置位置和撤销方法；
5. 不让 AI 在没有确认的情况下执行删除、发送或发布操作。

## 日志与截图脱敏

发布报错时可以保留：错误码、时间、工具版本、操作步骤和脱敏后的地址。必须删除：

- API Key、Cookie、Authorization 请求头；
- 邮箱、手机号、验证码和个人路径；
- 私有仓库地址和内部域名；
- 数据库连接串和服务器凭证。

## 发现泄露后的处理顺序

1. 立即撤销密钥或退出异常会话；
2. 创建新的凭证并更新本地配置；
3. 检查调用记录、余额和异常文件；
4. 从 Git 历史、截图和公开评论中清理泄露内容；
5. 记录发生原因，避免下一次重复。

## 发布前清单

- [ ] 文章、代码和截图中没有真实密钥；
- [ ] 练习项目不包含私人资料；
- [ ] MCP 示例默认是低权限或只读；
- [ ] 所有高风险操作都有人工确认；
- [ ] 读者知道如何撤销配置。
