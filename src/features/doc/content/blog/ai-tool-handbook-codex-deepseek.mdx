前面我们已经安装好了 Codex 客户端。本篇讲的是 Codex 接入 DeepSeek：安装 CC Switch，完成第一次基础配置，然后把客户端使用的模型切换到 DeepSeek。

本文面向第一次接触 API 和模型配置的小白，针对的是 Windows 上的 Codex 客户端，不讲 Codex CLI。你不需要手动编辑复杂的 `config.toml` 文件，只要准备好 DeepSeek API Key，按着界面一步一步操作即可。

本文核对时间：2026-08-10。

> 本文所说的 **CC Switch**，是指用于管理 Codex 等 AI 编程工具配置的桌面应用。下文有时简称为 CCS，不代表其他同名的命令行工具。

## 先说结论：为什么教程使用 Flash，不使用 Pro

DeepSeek 的模型名称可能会随着时间变化。以本文核对时的官方文档为准，DeepSeek 目前给 Codex 提供了专门的接入说明，其中 `deepseek-v4-flash` 是更适合本教程的选择；`deepseek-v4-pro` 的 Codex 支持则还没有和 Flash 一样稳定、直接。

选择 Flash，主要不是因为它一定“比 Pro 更强”，而是因为它更适合第一次配置：

- **官方 Codex 接入路径更明确**：DeepSeek 的官方 Codex 文档明确列出了 Flash 的接入方式。
- **配置更简单**：新版 CC Switch 的 DeepSeek 预设通常可以直接使用 Responses API，不需要额外启动本地协议转换路由。
- **出错环节更少**：少一层路由，就少一些 404、接口格式不匹配和流式输出解析错误。
- **更适合先验证流程**：第一次配置最重要的是确认“API Key 有效、Codex 能正常调用模型”，而不是一开始就追求最复杂的模型选项。

Pro 并不是完全不能尝试。某些版本的 CC Switch 可以通过 Chat Completions 加本地路由的方式使用 Pro，但它需要更多配置，也可能受到模型接口和 Codex 工具调用支持情况的影响。对于第一次使用的读者，建议先用 Flash 跑通，再考虑其他模型。

> 模型支持会变化。以后如果 DeepSeek 官方文档已经明确支持 Pro 接入 Codex，或者 CC Switch 的 DeepSeek 预设已经取消相关限制，可以按新版界面为准。

- [CC Switch 官方 DeepSeek 中文指南](https://github.com/farion1231/cc-switch/blob/main/docs/guides/codex-deepseek-routing-guide-zh.md)

## 你需要准备什么

- 一台 Windows 10 或 Windows 11 电脑；
- 已经安装并至少启动过一次 Codex 客户端；
- CC Switch 安装包；
- 一个 DeepSeek API Key；
- 一点 API 余额，用于发送测试请求。

如果你还没有启动过 Codex 客户端，可以先阅读前面的[下载安装教程](/blog/ai-tool-handbook-codex)，打开一次再退出。这样客户端会自动创建自己的配置目录。

如果你已经完成了上一章的 API 配置，也可以直接继续使用本篇的 DeepSeek 预设。上一章的[CC Switch 基础配置](/blog/ai-tool-handbook-codex-network)可以作为补充阅读。

在 Windows 中，这个目录通常是：

```text
C:\Users\你的用户名\.codex
```

如果找不到这个目录，先启动一次 Codex 客户端，再关闭它，然后重新打开文件夹查看。

## 先把四个词弄懂

第一次看到 CC Switch，最容易被这些词吓住。其实本文只需要理解下面四个：

| 词               | 小白理解                       | 本文怎么处理                        |
| ---------------- | ------------------------------ | ----------------------------------- |
| API Key          | 调用 DeepSeek 的密码           | 只复制到 CC Switch，不公开、不截图  |
| 供应商 Provider  | 一套模型连接配置               | 我们添加一套 DeepSeek 配置          |
| 预设 Preset      | 软件提前填好的模板             | 直接选择 DeepSeek，不手动填复杂参数 |
| 本地路由 Routing | CC Switch 在电脑上开的“翻译层” | 只有看到“需要路由”时才打开          |

你可以把整个过程想成点外卖：

- Codex 客户端是下单的 App；
- DeepSeek 是餐厅；
- API Key 是付款凭证；
- CC Switch 是帮你保存餐厅地址和付款方式的订单管理器；
- 本地路由是一个翻译员，只有 Codex 和餐厅说的“接口语言”不一样时才需要。

本文只使用“应用专属供应商”里的 DeepSeek 预设，不使用“统一供应商”、深度链接导入、JSON 编辑器、OAuth 登录或其他高级功能。第一次成功后，再研究这些功能。

## 第一步：下载并安装 CC Switch

建议从 [CC Switch 官方 GitHub 仓库](https://github.com/farion1231/cc-switch)进入 Releases 页面，下载 Windows 对应的安装包。

CC Switch 本身是免费的开源桌面应用。官方明确提醒：任何要求你给 CC Switch 充值、购买授权或提供 ChatGPT 登录密码的网站或客户端，都不是正常的 CC Switch 下载渠道。

下载时注意：

- 认准仓库名称和发布者；
- 优先选择官方 Releases 页面中的安装包；
- 不要从搜索引擎广告、网盘或陌生论坛下载所谓“增强版”；
- 安装前确认文件名和版本号，不要随意运行来源不明的脚本。

进入 Releases 页面后，向下滚动到当前版本的 `Assets` 区域，选择 Windows 安装包。不要点击 `Source code`，那是源代码压缩包，不是给普通用户直接安装的软件。

下载完成后，双击安装包，按照 Windows 安装向导完成安装。安装完成后，可以在开始菜单中搜索 `CC Switch` 并打开。

## 第二步：第一次打开后的基础配置

第一次打开 CC Switch，不要急着添加 API Key，先确认几个基础设置。

这一阶段只做三件事：确认 Codex 被识别、备份配置、找到正确的页面。看到其他高级设置时先不要改。

### 1. 确认 Codex 已被识别

在 CC Switch 的工具列表或顶部标签中，找到：

```text
Codex
```

如果能看到 Codex 页面，说明 CC Switch 已经找到了 Codex 客户端的配置位置。

如果看不到 Codex，可以检查：

- 是否已经启动过一次 Codex；
- 是否安装的是正式版 Codex 客户端；
- CC Switch 是否有权限访问用户目录；
- CC Switch 是否已经正常运行。

### 2. 先备份 Codex 配置

CC Switch 会帮助我们写入 Codex 配置，但第一次操作仍然建议手动备份。

按下：

```text
Win + R
```

输入：

```text
%USERPROFILE%\.codex
```

按回车，在打开的文件夹中找到：

```text
config.toml
```

把它复制到桌面，改名为：

```text
config.toml.backup
```

如果以后配置出错，可以关闭 Codex，再把备份文件复制回 `.codex` 文件夹。

### 3. 了解几个常见页面

CC Switch 中最常用的是三个页面：

| 页面            | 作用                                      |
| --------------- | ----------------------------------------- |
| Codex           | 添加、编辑和切换 Codex 客户端的模型供应商 |
| Routing（路由） | 管理需要协议转换的本地路由                |
| Usage / Logs    | 查看请求、模型和用量记录                  |

第一次配置 DeepSeek，主要会用到 `Codex` 页面；只有当供应商卡片显示 `Needs Routing` 时，才需要进入 `Routing` 页面。

以下设置本篇暂时不要碰：

- `统一供应商`：会把一套配置同步给多个 AI 工具，容易误改其他软件；
- `高级选项`：用于自定义接口格式、模型映射和思考能力；
- `模型映射`：只有预设识别失败或需要自定义模型时才用；
- `1M 上下文窗口`：不是接入 DeepSeek 的必需项；
- `Codex 应用增强`：和本篇的普通 DeepSeek API 接入不是一回事。

新手只需要完成：选择 Codex → 添加 DeepSeek 预设 → 填 API Key → 保存 → 启用。

{/* 截图 2：CC Switch 主界面，标出 Codex、Routing 和 Usage 入口。 */}

## 第三步：在 CC Switch 中添加 DeepSeek

点击顶部的 `Codex` 标签，进入 Codex 客户端配置页面。

然后点击右上角的：

```text
+
```

或者（中文界面可能显示为“添加供应商”）：

```text
Add Provider
```

在添加供应商页面中，优先选择内置的：

```text
DeepSeek
```

预设。

使用预设的好处是，Base URL、默认模型和接口格式通常已经配好，不需要新手自己猜参数。

如果添加面板上有两个标签，请选择：

```text
应用专属供应商
```

不要选择“统一供应商”。应用专属供应商只影响 Codex，比较适合第一次配置和排错。

{/* 截图 3：Codex 页面点击加号添加供应商。 */}

## 第四步：填写 DeepSeek API Key

进入 [DeepSeek 官方平台](https://platform.deepseek.com/)，创建自己的 API Key，然后复制到 CC Switch 的 API Key 输入框。

API Key 是调用 API 的凭证，可以理解成一把密码。不要把真实 Key 发到群里，也不要放进博客、截图或 GitHub 仓库。

截图时建议使用以下方式之一：

- 输入完成后立刻把输入框打码；
- 使用专门创建的测试 Key，截图后立即删除；
- 只截取字段名称，不截取输入框内容。

### Base URL 要不要手动填写？

如果使用的是 DeepSeek 内置预设，通常不需要修改 Base URL。

尤其不要把完整的接口路径随意填进去，例如：

```text
https://api.deepseek.com/chat/completions
```

不同协议需要不同的请求路径，CC Switch 会根据供应商的接口格式处理。手动多加路径，反而容易出现 404。

如果你没有使用预设，而是自己创建自定义供应商，就应该按照对应服务商的官方文档填写 Base URL 和模型名称。

### 模型选哪个？

本教程选择：

```text
deepseek-v4-flash
```

如果你的界面显示的模型名称略有不同，不要直接照抄文章中的名字，以 CC Switch 当前预设中显示的模型为准。

不要为了“看起来更高级”去手动修改模型 ID。只要预设里已经有 Flash，就直接使用预设显示的 Flash 模型。

{/* 截图 4：DeepSeek 预设页面，API Key 必须打码，模型选择 Flash。 */}

填写完成后，点击：

```text
Save
```

## 第五步：启用 DeepSeek

保存后回到 Codex 供应商列表，找到刚刚添加的 DeepSeek 卡片。

点击（中文界面可能显示为“启用”）：

```text
Enable
```

启用后，重点观察卡片上有没有：

```text
Needs Routing（需要路由）
```

这是整篇教程最重要的判断点。不要根据网上旧教程猜自己要不要开路由，直接看你当前卡片上的标记：

| 你看到的状态             | 你要做什么                      |
| ------------------------ | ------------------------------- |
| 没有 `Needs Routing`     | 不开本地路由，直接重启客户端    |
| 有 `Needs Routing`       | 打开本地路由，并启用 Codex 接管 |
| 显示需要路由但路由未启动 | 先启动路由，再点 Enable         |

CC Switch 官方文档之所以有两种写法，是因为旧版本 DeepSeek 预设、旧配置和新版预设可能使用不同的上游协议。对小白来说，卡片标记比文章里的版本号更可靠。

### 没有 Needs Routing：直接使用

如果没有这个标记，说明当前预设使用的是 Responses 直连模式。

这时不需要打开本地路由，直接重启 Codex 即可。

这是当前新版 DeepSeek Flash 预设最简单的情况。

### 有 Needs Routing：开启本地路由

如果卡片上出现 `Needs Routing`，说明当前配置需要 CC Switch 做接口格式转换。

进入（中文界面可能显示为“设置 → 路由 → 本地路由”）：

```text
Settings → Routing → Local Routing
```

依次打开：

```text
Routing Master Switch
Codex
```

CC Switch 默认可能会启动一个本地地址，例如：

```text
127.0.0.1:15721
```

这个地址是 CC Switch 的本地路由服务，不是 DeepSeek 的 API 地址，也不要和其他代理软件的端口混淆。

如果你看到“需要本地路由映射”已经自动打开，不要再手动修改模型映射表。预设已经把模型 ID、显示名称和上下文配置填好了。

只要是“需要路由”的模式，CC Switch 就必须保持运行。可以把它最小化到 Windows 右下角的系统托盘，但不要直接退出，否则本地路由服务也可能一起停止。

{/* 截图 5：保存后的 DeepSeek 卡片，清楚显示是否有 Needs Routing。 */}
{/* 截图 6：如果出现 Needs Routing，截取 Local Routing 页面。 */}

## 第六步：先直接验证，不要默认重启

配置切换后，CC Switch 不需要重启；如果是 Claude Code，也不需要重启，热更新会读取新的供应商配置。

Codex 先不要默认重启，直接新建一个会话发送测试任务。如果当前 Codex 仍然显示旧的模型、旧的 provider 或旧的 API Key，再完全退出 Codex 客户端并重新启动。

如果修改了模型映射、模型目录或其他启动时读取的配置，则直接退出并重启 Codex 更稳妥。

如果 Codex 是 ChatGPT 桌面应用中的功能，重启时要完全退出 ChatGPT，再重新打开；只关闭当前对话有时不够。

CC Switch 本身继续保持运行，尤其是启用了本地路由时，不要退出 CC Switch。

## 第七步：在 Codex 客户端中验证

客户端中不使用命令行验证，按下面的方式检查：

1. 确认 CC Switch 的 DeepSeek 卡片仍然显示 `Enabled`；
2. 新建一个 Codex 会话；
3. 发送一个简单的代码任务；
4. 查看 Codex 是否正常返回结果；
5. 如果使用了本地路由，再回到 CC Switch 的 Usage 或 Logs 页面查看请求记录；如果是直连模式，路由日志里没有请求也是正常的。

桌面版 Codex 不一定提供和 CLI 一样的 `/status`、`/model` 命令，也不一定有独立的模型选择菜单。看不到这些入口不代表配置失败，先以供应商状态和实际请求结果为准。

测试任务可以使用：

```text
请创建 hello.py，输出 Hello DeepSeek，并告诉我你修改了哪些内容。
```

第一次测试不要直接让 Codex 修改重要项目，也不要把密码、生产环境配置或公司内部代码粘进去。

## 常见问题

### 报错 404，提示找不到 `/responses`

常见原因是把 Chat Completions 地址直接填进了 Codex，或者本地路由没有启动。

可以按这个顺序检查：

1. 删除手动填写的完整接口路径；
2. 重新使用 DeepSeek 内置预设；
3. 查看卡片上是否有 `Needs Routing`；
4. 如果有，打开 Local Routing；
5. 先直接发送最小测试请求；
6. 仍然使用旧配置时，再退出并重启 Codex，不要重启 CC Switch。

### 卡片显示 Needs Routing，但请求没有返回

进入：

```text
Settings → Routing → Local Routing
```

确认以下两个开关都已打开：

```text
Routing Master Switch
Codex
```

### 模型列表为空

尝试保存供应商、重新启用，然后先直接发送一次最小请求；如果模型目录仍为空，再完全退出 Codex 再启动。CC Switch 不需要重启。

如果仍然没有模型，检查 Codex 和 CC Switch 的版本是否过旧。新版本模型目录可能需要重新生成，老版本客户端也可能无法识别新的模型配置。

### API Key 无效

检查：

- Key 是否复制完整；
- 前后是否多了空格；
- Key 是否已经被删除或重新生成；
- DeepSeek 账户是否有可用余额；
- 当前模型是否在你的账户或 API 接口中可用。

### 请求成功，但 Codex 的工具调用不正常

模型能够返回文字，不代表它和 OpenAI 模型具备完全一致的 Codex 工具能力。补丁操作、命令执行、推理参数和上下文长度都可能受到具体模型与适配层影响。

因此建议先使用官方明确支持 Codex 的 Flash 模型验证流程，再尝试其他模型。

## API Key 安全提醒

API Key 等同于账户密码。

不要把它放进：

- 博客文章；
- GitHub 仓库；
- 截图；
- 评论区；
- 项目源码；
- `README.md`；
- 发给别人代配置的压缩包。

如果怀疑 API Key 泄露，应立即到 DeepSeek 平台删除旧 Key，并重新创建一个新的 Key。

## 总结

完整流程就是：

```text
安装 CC Switch
→ 启动过 Codex
→ 备份 config.toml
→ Codex 客户端页面添加 DeepSeek 预设
→ 填入 API Key
→ 选择 Flash
→ Enable
→ 根据 Needs Routing 决定是否开启本地路由
→ 重启 Codex
→ 用客户端测试结果和请求日志验证
```

对小白来说，第一次配置最重要的是选择官方预设、少改参数、先用 Flash 跑通流程。等基本调用正常之后，再研究 Pro、自定义供应商和本地路由，会更容易定位问题。
