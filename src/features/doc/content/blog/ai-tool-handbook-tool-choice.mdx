这些工具解决的问题不在同一层。选择时先看任务，再看工具，不要因为“别人都在用”就全部安装。

## 一张选择表

| 你想完成的事                        | 优先理解什么                 |
| ----------------------------------- | ---------------------------- |
| 让 AI 读代码、改文件、跑验证        | Codex 或 Claude Code         |
| 让 AI 访问额外文件、GitHub 或数据库 | MCP                          |
| 让 AI 重复执行固定流程              | Skills                       |
| 只想聊天或解释一段代码              | 先使用现有客户端，不必加 MCP |

## Codex 和 Claude Code

两者都可以参与项目协作，差异主要在产品生态、登录方式、终端体验和当前版本支持的能力。第一次选择时问自己：

- 我已经登录并能正常使用哪一个？
- 我的项目规则文件和团队习惯偏向哪一个？
- 我需要桌面应用、编辑器体验还是终端工作流？
- 任务是否需要特殊模型或 API 渠道？

不要用一次回答质量就判断长期工具。更重要的是目录边界、diff 检查、验证命令和团队可维护性。

## 什么时候需要 MCP

只有当 AI 需要访问当前对话之外的工具或数据时，才考虑 MCP。例如读取一个受控资料目录、总结 GitHub Issue 或查询只读数据库。

如果把文件直接拖进对话就能完成任务，不需要为了“看起来高级”再配置 MCP。MCP 增加了权限和维护成本。

## 什么时候需要 Skills

当你已经连续多次执行同一套流程，并且步骤、输入和输出都比较稳定时，再把它写成 Skill。先手动跑通，再固化；否则只是把还没想清楚的流程藏进一个文件。

## 最小组合

对完全新手，推荐的最小组合是：

1. 一个能正常登录或调用的 AI 客户端；
2. 一个可删除的练习项目；
3. 一份 `AGENTS.md` 或项目规则；
4. 一套查看 diff 和运行验证的习惯。

MCP 和 Skills 都可以等你遇到明确需求后再添加。

## 选择前的五个问题

- 这件事没有工具扩展能否完成？
- 需要读什么数据，是否包含私人信息？
- 工具是否会写入、删除或执行命令？
- 出错后能否撤销？
- 团队中的其他人能否理解和维护这套配置？
