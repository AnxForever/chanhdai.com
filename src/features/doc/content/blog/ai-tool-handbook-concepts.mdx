很多新手第一次配置 AI 工具时，会把“能不能登录”“有没有订阅”“API 能不能调用”和“模型是否支持”当成同一个问题。它们其实是不同层次，这一篇只负责把关系理顺。

> 本文核对时间：2026-08-10。产品名称和计费规则可能变化，本文只解释稳定的概念，不承诺某个具体服务的当前价格或可用性。

## 先记住一句话

**账号解决身份，订阅解决某种产品权益，API Key 解决程序调用权限，模型负责处理请求，渠道决定请求从哪里走。**

## 四个核心名词

| 名词    | 白话解释                       | 出问题时先查什么               |
| ------- | ------------------------------ | ------------------------------ |
| 账号    | 你用来登录网站或客户端的身份   | 邮箱、登录状态、验证和账号限制 |
| 订阅    | 某个产品账号下购买的服务权益   | 当前产品规则、账单和权益页面   |
| API Key | 程序调用 API 的密钥            | Key 是否有效、权限和余额       |
| 模型    | 处理文字、代码或工具调用的能力 | 模型名、接口支持和服务商文档   |

还有一个连接这些概念的词：**渠道**。渠道包含请求地址、认证方式、接口协议和模型映射。即使 API Key 正确，如果 Base URL 或协议不匹配，请求仍然会失败。

## 用一个比喻理解

把 AI 工具想成餐厅：

- 账号像会员卡，证明你是谁；
- 订阅像会员权益，决定你能使用哪些套餐；
- API Key 像给外卖程序使用的付款凭证；
- 模型像真正做菜的厨师；
- 渠道像外卖平台记录的餐厅地址和下单格式；
- Codex 或 Claude Code 是你用来下单的应用；
- MCP 是让应用可以取用额外工具或资料的连接方式。

这个比喻不代表实际计费规则，只帮助你定位问题所在。

## 客户端登录和 API 调用不是一回事

你可以成功登录客户端，但没有配置 API；也可以拥有 API Key，但客户端账号没有登录。这两种状态都可能造成“工具不能用”，但修复方法完全不同。

排查时先问自己：

1. 我现在是在登录网页/客户端，还是在发送 API 请求？
2. 错误发生在打开应用、授权账号，还是发送任务之后？
3. 我使用的是账号权益，还是某个 API 渠道？

不要因为登录失败就立刻重建 API Key，也不要因为 API 401 就反复修改账号密码。

## API Key 为什么要当密码保护

API Key 往往可以代表你的账户发起请求并产生费用。它不应该出现在：

- Git 仓库和 `.env` 以外的公开文件；
- 教程截图和录屏；
- 群聊、评论和工单；
- 提交给 AI 读取的无关日志；
- 浏览器前端代码或带 `NEXT_PUBLIC_` 前缀的环境变量。

如果怀疑泄露，最短处理路径是：**立即撤销旧 Key → 创建新 Key → 检查用量 → 搜索并删除泄露位置**。不要只修改变量名。

## 模型和渠道为什么要一起看

一个服务商可能提供多个模型，但并不代表每个模型都支持代码编辑、流式输出或工具调用。一个渠道也可能只兼容某种接口协议。

看到报错时，按这个顺序确认：

1. 服务商文档是否写明支持当前工具；
2. Base URL 是否是基础地址；
3. 模型名称是否完全匹配；
4. API Key 是否有对应权限和余额；
5. 是否需要本地路由或协议转换。

## 一个最小判断练习

假设你看到三种现象：

| 现象                      | 更可能的问题           | 不要先做什么           |
| ------------------------- | ---------------------- | ---------------------- |
| 客户端打不开登录页        | 登录、网络或客户端问题 | 不要先换模型           |
| 登录成功但请求 401        | Key 或 API 权限问题    | 不要先改 UI 提示词     |
| 请求 404 且提示接口不存在 | URL 或协议问题         | 不要无限重试同一个地址 |

这不是绝对规则，但能帮助你先查对层次。

## 完成检查

- [ ] 我能解释账号和 API Key 的区别；
- [ ] 我知道模型名不等于渠道地址；
- [ ] 我知道 401、404 通常要查不同地方；
- [ ] 我不会把真实 Key 放进截图或公开代码；
- [ ] 我知道配置前要看服务商官方文档。
