安装和登录完成后，不要马上让 AI 改真实项目。这一篇会创建一个可以随时删除的练习目录，让 Codex 先阅读，再计划，再做一个很小的修改，最后由你检查结果。

> 本文核对时间：2026-08-10。不同客户端的按钮名称可能变化，但“先读、再改、再验证”的流程不变。

## 你将完成什么

- 创建一个安全的练习目录；
- 让 Codex 只读文件并解释内容；
- 让 Codex 修改一个小标题；
- 查看差异并确认修改结果。

## 第一步：创建练习目录

在桌面创建一个文件夹，命名为：

```text
codex-first-task
```

在里面新建 `README.md`，写入：

```markdown
# 我的第一个 AI 项目

这是一个只用于练习的项目。

## 目标

让标题更清楚，并保留原来的项目说明。
```

这个文件没有密码、个人资料或重要代码，所以即使练习失败，也可以直接删除后重来。

## 第二步：让 Codex 先读取

打开 Codex，进入刚刚创建的 `codex-first-task` 目录。第一次不要直接下“帮我改好”的命令，先发送：

```text
请先读取当前目录的 README.md，用三句话说明：它现在是什么、目标是什么、你建议改哪里。暂时不要修改任何文件。
```

你要观察的是：Codex 是否真的读取了文件，回答是否和文件内容相符，以及它有没有在你明确说“不要修改”时保持只读。

## 第三步：让它先说计划

如果读取结果正常，再发送：

```text
请先列出修改计划，不要执行。目标是让 README 的标题更具体，但不要改动“目标”这一节，也不要新增文件。
```

这一步的意义是让修改边界变得可检查。一个好的计划应该说明会改哪个文件、改哪一行、不会做什么。

## 第四步：执行一个小修改

确认计划没有超出范围后，再发送：

```text
按照刚才的计划执行。只修改 README.md 的一级标题。完成后告诉我修改了什么，并不要运行其他命令。
```

如果客户端提供确认按钮，先阅读变更再选择接受。不要因为 AI 说“已完成”就跳过差异检查。

## 第五步：查看结果

README 的标题可以从：

```markdown
# 我的第一个 AI 项目
```

改成更具体的标题，例如：

```markdown
# 用 Codex 完成的第一个练习项目
```

你需要确认：

- 只有 `README.md` 被修改；
- 只有一级标题发生变化；
- “目标”一节还在；
- 没有新增或删除文件；
- 文件仍然可以正常打开。

## 这次任务到底发生了什么

你刚刚完成的是一个最小协作闭环：

1. 给 AI 一个明确的工作目录；
2. 让 AI 获取上下文，但先不允许修改；
3. 先看计划，确认范围；
4. 允许一个低风险修改；
5. 由人检查差异和结果。

以后处理真实项目时，仍然使用这条链路，只是文件和验收标准会更复杂。

## 如果结果不对

### AI 修改了不该改的文件

立即停止后续操作，查看 diff，撤销不需要的变更。先确认 Codex 当前打开的目录是不是练习目录，再重新发送带有“只修改某个文件”的任务。

### AI 没有读取 README

检查当前工作目录、文件名和文件是否保存。让它先执行目录查看或明确读取指定文件，不要直接进入大任务。

### AI 说完成了，但文件没变

检查它是否只是给出建议、是否等待确认，以及你查看的是不是同一个目录。成功标准是文件内容真的变化，而不是对话里出现了“完成”。

## 完成检查

- [ ] 练习目录中没有真实密钥和重要资料；
- [ ] AI 先读取、再计划、再修改；
- [ ] 修改范围只有一个文件和一个标题；
- [ ] 你看过 diff 或修改前后的内容；
- [ ] 你知道如何撤销这次练习。
